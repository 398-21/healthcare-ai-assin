# Task 2 data and preprocessing

This page documents the current Task 2 inputs generated by `src/task2_mortality/preprocess.py` and `src/task2_mortality/derived_features.py`. The raw files remain unchanged. The preprocessing rules are configured in `src/task2_mortality/config.json`.

## Cohort and split

Task 2 uses all **12,000** released ICU stays and the recorded `In-hospital_death` label (1,707 deaths). It retains the 167 stays with `Length_of_stay = -1`: length of stay is neither a predictor nor a cohort filter. The source release itself contains ICU stays of at least 48 hours, which makes the 48-hour prediction point available for this cohort.

Measurements from `[0, 48 h)` are used to predict recorded in-hospital death before hospital discharge, including deaths after ICU discharge. The frozen, patient-level stratified split uses seed `20260907`:

| Split | Stays | Deaths | Prevalence |
|---|---:|---:|---:|
| Train | 8,400 | 1,195 | 0.14226 |
| Validation | 1,800 | 256 | 0.14222 |
| Test | 1,800 | 256 | 0.14222 |

Task 1 has its own stay-level split; do not assume its train/validation/test IDs match Task 2.

## Cleaning and feature construction

Cleaning is performed at the observation level. It does not remove a patient stay from the cohort:

- Invalid times, blank parameters, unknown parameters, invalid/non-finite values, and observations after 48:00 are excluded from the primary summaries. Exact `48:00` rows are excluded from primary features and written to a separate sensitivity file for the 234 affected stays.
- The `-1` missing sentinel and values outside the shared physiological ranges in `src/shared/physiology.py` are treated as missing; values are not clipped. Before range checks, pH values above 14 are divided by 100, and heights below 100 cm are multiplied by 100.
- Exact duplicates and same-time conflicts are audited. Same-time continuous measurements are collapsed by median, `MechVent` by maximum, and `Urine` by sum before time-window summaries. Static descriptor conflicts are recorded in the quality flags.
- The 1,474 base features summarize 37 dynamic parameters over `[0,24 h)`, `[24,48 h)`, and `[0,48 h)`, plus static descriptors, merged blood-pressure streams, and record-level counters. `Weight` is retained as an admission descriptor and in its observed time series.
- The train-fitted fill values use training medians; columns entirely missing in train use 0 and are flagged. The exported `X_*_imputed.csv.gz` files are convenience matrices. Model pipelines fit their own imputers/scalers on training folds; tree models use the unimputed values and native missing-value handling.
- `derived_features.py` adds 42 clinical features, including merged blood-pressure summaries, BMI, P/F ratio, shock index, BUN/creatinine ratio, urine output per kg-hour, and rule-based organ sub-scores. The unfiltered modeling matrix therefore has 1,516 predictors; the train-fitted feature filter retains 1,163 for the selected CatBoost pipeline.
- `SAPS-I`, `SOFA`, `Length_of_stay`, and `Survival` are excluded from model predictors. SAPS-I and SOFA are kept separately as bedside-score comparators; `-1` scores become missing and have availability flags.

## Main generated files

| File | Shape / content | Use |
|---|---|---|
| `patient_features_unimputed.csv.gz` | 12,000 rows x 1,475 columns (RecordID + 1,474 predictors) | Base feature matrix; tree pipeline inputs after adding derived features |
| `derived_features.csv.gz` | RecordID + 42 derived predictors per stay | Task 2 clinical feature engineering |
| `X_train_imputed.csv.gz` | 8,400 x 1,475 | Train-median-imputed base features |
| `X_validation_imputed.csv.gz` | 1,800 x 1,475 | Validation base features |
| `X_test_imputed.csv.gz` | 1,800 x 1,475 | Test base features |
| `labels_and_splits.csv` | RecordID, death label, frozen split | Cohort and split reference |
| `labels_and_baselines.csv` | Death label, split, SAPS-I/SOFA values and availability flags | Model ladder and bedside-score comparisons |
| `patient_features_48h_inclusive_affected_rows.csv.gz` | Boundary-inclusive rows for 234 affected stays | Sensitivity analysis only; not additional training rows |
| `quality_flags_by_stay.csv`, `preprocessing_summary.json`, `independent_verification.json`, `manifest.sha256` | Per-stay QA, run summary, independent checks, hashes | Audit and reproducibility |

The feature dictionary and variable units are in `preprocessed/task2_mortality/feature_dictionary.csv` and `data/README.md`. Run the pipeline and checks from the repository root:

```powershell
python -m src.task2_mortality.preprocess
python -m src.task2_mortality.verify_outputs
python -m src.task2_mortality.validate_phase3_outputs
```
